# Implementation Plan: Intoxalock Device Removal Call Automation

**Branch**: `001-device-removal-call` | **Date**: 2026-06-10 | **Spec**: [spec.md](./spec.md)

## Summary

Build a two-part POC: a React + MUI frontend where customers submit their name and phone number to request an Intoxalock interlock device removal, and a Node.js Lambda backend that receives the request and triggers an outbound AI phone call via the ElevenLabs Conversational AI API. The system follows Clean Architecture throughout, with all secrets read from Lambda environment variables.

## Technical Context

**Language/Version**: TypeScript 5.x (frontend + backend)

**Primary Dependencies**:
- Frontend: React 18, Vite 5, MUI v6, React Hook Form, Zod, `mui-tel-input`, `libphonenumber-js`
- Backend: Node.js 18 (Lambda runtime `nodejs18.x`), native `fetch`, Zod (shared validation)

**Storage**: None (no persistent database; call records tracked by ElevenLabs/Twilio)

**Testing**:
- Frontend: Vitest + React Testing Library
- Backend: Jest + `ts-jest`

**Target Platform**: AWS (Lambda + API Gateway + S3 + CloudFront) + browser (modern evergreen)

**Project Type**: Web application — React SPA frontend + serverless Lambda backend

**Performance Goals**:
- Call initiation within 5 seconds of valid form submission (SC-002)
- Confirmation screen load within 3 seconds of API response (SC-005)

**Constraints**:
- No authentication required (POC)
- No persistent database
- No rate limiting (POC, controlled environment)
- Secrets via Lambda environment variables only
- All copy in English

**IaC**: Terraform (replaces SAM) — manages Lambda, API Gateway, S3 bucket, CloudFront distribution, IAM roles

**Scale/Scope**: POC — single-region AWS, single Lambda function, single-page frontend hosted on S3 + CloudFront

## Key Design Decisions

### Clean Architecture Layer Responsibilities

**Domain layer** (both frontend and backend):
- Pure TypeScript entities and interfaces — zero framework dependencies
- `RemovalRequest`, `CallRecord` entities with validation rules
- `ICallService` port (backend) — interface that `ElevenLabsCallService` implements

**Application layer**:
- Frontend: `submitRemovalRequest` use case — orchestrates form data → API call → result handling
- Backend: `InitiateRemovalCallUseCase` — validates payload, delegates to `ICallService`, returns `CallRecord`

**Infrastructure layer**:
- Frontend: `callRequestClient` — `fetch` wrapper for `POST /api/v1/call-request`
- Backend: `ElevenLabsCallService` — implements `ICallService`, calls ElevenLabs API with env var credentials

**Presentation layer**:
- Frontend: React components + MUI theme — no business logic, calls application use cases only
- Backend: `callRequestHandler` — thin Lambda handler, parses event, calls use case, formats HTTP response

### TCPA Consent

The consent checkbox renders a text label with an inline link to a Terms & Conditions page. The T&C text confirms the customer authorizes Intoxalock to contact them via automated call under TCPA. The Submit button is disabled until the checkbox is checked. The backend also validates `tcpaConsent === true` and rejects with `400` if not present.

### Error & Retry Flow

On API error, the frontend transitions to an error state showing the error message and a "Try Again" button. Clicking "Try Again" re-invokes `submitRemovalRequest` with the same `RemovalRequest` data held in component state — no re-entry required.

### Environment Variables (Backend Lambda)

| Variable | Description |
|----------|-------------|
| `ELEVENLABS_API_KEY` | Authenticates requests via `xi-api-key` header |
| `ELEVENLABS_AGENT_ID` | ID of the configured ElevenLabs Conversational AI agent |
| `ELEVENLABS_AGENT_PHONE_NUMBER_ID` | ID of the Twilio phone number linked to the agent |

Set in `infra/lambda.tf` under the Lambda `environment.variables` block, sourced from `terraform.tfvars` locally (never committed) and from CI/CD secrets on deploy.

**Deploy flow**:
1. `terraform apply` — provisions all AWS resources
2. `npm run build` in `frontend/` → `aws s3 sync dist/ s3://<bucket>` → `aws cloudfront create-invalidation`
3. `zip` Lambda source → `terraform apply` (or upload directly for POC)
